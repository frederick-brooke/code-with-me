# ADR-0006: The Assessor leads a live, five-phase interview arc over Working Code snapshots

The Assessor is the interviewer, not just a voice interface to a timer: it drives the Session through five live phases — Introduction, Clarifying, Approach, Implementation, Wrap-up — ending in Debrief, and it decides when the interview is over. To do that it needs (a) a view of the Candidate's in-editor code between Runs, (b) the ability to move the Session between phases, and (c) natural opportunities to speak. We made three decisions to deliver this without putting our server in the audio path and without trusting the agent prompt alone:

- **Working Code snapshots.** The editor auto-saves a debounced (~2–5s idle) snapshot to the Session, and `get_session_state` serves it alongside the last Run's counts, run count, seconds since the last Run, and seconds since the last recorded activity. The Assessor reads where the Candidate actually is — but the snapshot is current state, not an event, so the agent is never driven keystroke-by-keystroke. This relaxes the "reacts only to explicit events" rule in `CONTEXT.md` (Run) from a ban on keystrokes to a ban on keystroke-churn.
- **Phase advancement is a backend tool.** The Assessor calls a `set_phase` webhook tool to move the Session through the arc (e.g. "great, let's talk through your approach" + advance). The engine stays the source of truth and the tool is the only writer of phase changes from the conversation side; the Candidate's "end from anywhere" still works as a hard escape hatch. A wrong stage label is recoverable, so prompt-reliance here is acceptable (unlike hint policy, ADR-0001).
- **Proactive-but-candidate-paced speech.** Proactivity comes from explicit events and natural silence, not fabricated turns: contextual updates on Run completion and phase changes, `user_activity` pings while the Candidate types (so the agent does not barge in mid-thought), and patient turn settings so a genuine pause produces a grounded "where are you at?". No synthetic `user_message` turns. The agent config is codified in `assessor:configure` including a raised `conversation.max_duration_seconds` (the 600s default would kill the arc mid-Implementation).

Two flow rules fall out of the phase model: a failing Run keeps the Session in Implementation (the Assessor asks why it might fail and guides); a passing Run is the natural cue for the Assessor to propose Wrap-up — and, if the Candidate is satisfied, to end. Ending closes the live Conversation and moves the Session to Debrief, where the Performance Summary is produced as the exit artifact (written, never spoken; the call closes while it is generated).

Transcript ingestion (the `message` store is populated from the live Conversation so the Session Record and the Summary are fed a real history) and a live transcript sidebar complete the "watching" surface.

Supersedes the "Candidate initiates the move from Solve to Wrap-up" wording in `CONTEXT.md` (Session) and the four-phase model in `spec-mvp.md` / `prd.md`.
