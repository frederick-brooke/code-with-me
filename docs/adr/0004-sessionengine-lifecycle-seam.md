# ADR-0004: SessionEngine is the single Session lifecycle seam

The SessionEngine (`lib/engine/session-engine.ts`) is the single seams owner of one Session lifecycle, mirroring the spec's "single-seam" decision: a UI-free engine over the data store seam, testable headlessly. It starts a Session on a seeded Problem (rejecting unknown Problems), records every Run and transcript message through the seam, and owns the phase state machine — Introduction → Solve → Wrap-up → Debrief — where `advance` follows the agreed order and `end` lands in Debrief from any phase, writing `endedAt`. Its query surface returns the Candidate's current code (the latest Run's snapshot, falling back to the Problem's starter template), the visible pass/fail counts, and the transcript. To persist lifecycle transitions it added `updateSession` to the `DataStore` seam (in-memory and Postgres implementations), keeping the store interface the single point of contact — consistent with ADR-0002's async, store-agnostic seams. The Assessor's tool endpoints are thin adapters over this seam; the voice/tool layer is deliberately kept out of the engine.
